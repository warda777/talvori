# Phase 2G-M13-B Early Island Onboarding Choice Preview

Stand: 2026-06-06

## Zweck

Diese Preview-Dateien visualisieren, wie Talvori eine fruehe Foundation-Wahl
planen kann, ohne eine finale Startinsel, einen Pflicht-Hausstart oder eine
irreversible Erstentscheidung zu erzwingen.

M13-B ist ein reiner Planungs- und Visualisierungsblock. Die Dateien sind keine
finale Onboarding-UI, keine Spielassets, keine App-Integration und keine
Codefreigabe.

## Dateien

| Datei | Inhalt |
| --- | --- |
| `01_onboarding_choice_flow.png` | Reversibler Onboarding-Flow von Welcome ueber Tali/Vori-Erklaerung und Foundation-Wahl bis Safe Start und Backlog-Fallback. |
| `02_foundation_choice_cards.png` | Vergleich der Foundation-Kandidaten Zuhause / Alltag, Schule / Lernen und Garten / Natur nah. |
| `03_onboarding_variant_comparison.png` | Vergleich von Single recommended start, Three-card choice, Question-based routing, Starter test flow und Hybrid. |
| `04_no_forced_start_guardrails.png` | Guardrails gegen Pflichtstart, Lock-in, Premium-Druck, automatische Platzierung und Umsetzung. |

## Prueffazit

Die Previews zeigen die Foundation-Wahl verstaendlich als persoenlichen
Lernfokus. Der `Hybrid`-Ansatz wirkt als erste Planungsrichtung am staerksten:
kurze Tali/Vori-Frage, drei Foundation-Karten, reversible Bestaetigung und
sicherer Codex-/Blueprint-/Backlog-Fallback fuer nicht passende Woerter.

Die Texte bleiben innerhalb der Karten, Rahmen und Panels. Die Ansicht ist
lesbar und bewusst als internes Planungsdiagramm gestaltet.

## Grenzen

- Keine finale Onboarding-UI.
- Keine finale Startinsel.
- Keine finale ThemeIsland-Roadmap.
- Keine ThemeIsland-Umsetzung.
- Keine finale Datenstruktur.
- Keine Runtime-Konfiguration.
- Keine App-Integration.
- Keine Assetfreigabe.
- Kein Code.
- Kein `frame_started`.

## Sichtbare Risiken

- Zuhause / Alltag darf nicht als Pflicht-Hausstart gelesen werden.
- Schule / Lernen braucht emotionale Darstellung und Mobile-/Clutter-Pruefung.
- Garten / Natur nah braucht Fairness-/Timer-Regeln vor jeder Umsetzung.
- Die Erstwahl muss spaeter aenderbar bleiben.
- Unpassende Woerter muessen sicher in Codex, Blueprint oder Backlog bleiben.

## Naechster Schritt

Erlaubt ist nur die visuelle Pruefung von M13-B oder eine dokumentarische
Nachbesserung. Eine Onboarding-Implementierung, finale UI, Startinsel-
Festlegung, App-Integration oder Assetproduktion ist aus M13-B nicht erlaubt.
